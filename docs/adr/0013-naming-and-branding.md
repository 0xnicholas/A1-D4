# 命名与品牌:对外名 balsa,npm scoped `@balsa/*`,GitHub 个人账号同名仓库

对外项目名定为 **balsa**——最轻的结构木材,"轻但能承重",是「按需组合 + 无运行时负担」(ADR-0001)这一轴的现成隐喻;代号 A1-D4(Attempt 1, Draft 4)退役为历史。npm 采用 **scoped 命名空间**:核心包 `@balsa/core`,能力包一律 `@balsa/<能力>` 短名词、无类型后缀——首版清单 `@balsa/mcp-server`、`@balsa/mcp-client`、`@balsa/otlp`、`@balsa/sqlite`、`@balsa/ai-sdk`、`@balsa/bunfold`;非 scoped `balsa` 已被一个浏览器日志库占用,不争取。GitHub 归属 = 个人账号原地改名 `0xnicholas/balsa`(org 名 `balsa` 被占,派生 org 会造成品牌与仓库不同名的割裂)。定位一句话(英文,兼作 repo description 与 README 首句):"Balsa is an ultralight TypeScript agent framework — compose only what you use, run anywhere, no runtime baggage."

## Considered Options

- **沿用代号 A1-D4**:被否——`a1d4` 在 npm 非 scoped、npm scope、GitHub 三处全空(2026-09-28 查实)且暗合机器人命名,但零表意,候选词中 balsa 的隐喻与「轻量」轴直接对齐,表意价值压过蹲守便利。
- **争取非 scoped `balsa` 转让**:被否——现占用方为低活跃浏览器日志库(1.1.0,2025-01 最后更新),协商周期不可控,而命名是 M1 末 0.1 发布的门(见 #16),不能堵。
- **非 scoped 派生名(`balsa-core`、`balsa-mcp-server` 式)**:被否——不合 TS 生态惯例,能力包名无命名空间保护、易被蹲;scoped 与「按需组合」的包结构(ADR-0002)一一对应。
- **新建 GitHub org 派生名(`balsa-ai`/`balsafw` 等)**:被否——`balsa` org 名已被占,任何派生 org 都让品牌与仓库地址不同名;个人账号同名仓库保留完整品牌面,未来需要时仍可迁入 org(GitHub 迁移自带 redirect)。

## Consequences

- M1 末 0.1 发布门的「定名」前置解除(见 `docs/ROADMAP.md`)。
- 发布 0.1 前需创建 npm org `@balsa`(截至 2026-09-28,该 scope 名下无任何已发布包,可申领;`@balsa/core` 等全部 FREE);org 创建依赖 owner 的 npm 账号,属 M1 实施期 task。
- `CONTEXT.md` 更名为 Balsa 并登记核心包/能力包的具体包名;`AGENTS.md` 同步仓库名;文档内 issue 链接统一改写为 `0xnicholas/balsa`(旧 `0xnicholas/A1-D4` 链接经 GitHub redirect 仍有效)。
- **修订(改名 balsa-framework,2026-09-30)**:对外品牌名 **balsa 不变**,但**项目/仓库名定为 `balsa-framework`**——Balsa 是伞形品牌,框架只是其下第一个子项目,未来子项目平行共存(对照 mastra:伞形 `mastra` / `@mastra/*`,framework 只是其中一个仓);本 ADR 原裁「个人账号同名仓库」的前提随之作废,仓库已原地改名为 `0xnicholas/balsa-framework`。**重定向实测**:仓库根 / `/blob` / `/pull/NN` / `/issues` 列表与 git 协议、API(按 repository id)均 301 有效;但**网页 `/issues/NN` 深链不可假定**——改名后逐步传播,实测部分 301、部分仍 404,故文档内引用已统一改写为新仓库名,历史 tracker 链接以 `gh issue view <n>` 或换名后 URL 访问(本文件正文按 ADR 惯例保留当时的记录)。**npm scope 不变**:`@balsa/*` 归伞形品牌、核心包仍 `@balsa/core`、未来子项目共用同一 scope——非 scoped `balsa` 被占的约束与 scoped 短名词的理由均未变。定位句(兼作 repo description 与 README 首句)与 `CONTEXT.md` 的对外名不变。依据 [改名:balsa → balsa-framework](https://github.com/0xnicholas/balsa-framework/issues/62) 决议评论。
- 公共面(README、npm、GitHub description)英文为主;中文文档现状不动。
- (澄清 2026-09-28)公共面含 npm 产物里的公开代码 JSDoc:`packages/**/src` 中会 emit 进 `.d.ts` 的注释用英文;仓库内部文档与实现注释维持中文。
- **修订(标识根 balsats,2026-10-02)**:对外**标识根**(域名 / npm scope / GitHub 组织这一层)改为 **`balsats`**(balsa + ts 生态后缀);**品牌名 balsa 不变**、仓库名 `balsa-framework` 不变、定位句(README 首句兼 repo description)不变——换的是落地标识,不是品牌。**npm scope 由 `@balsa/*` 改为 `@balsats/*`**(本 ADR 2026-09-30 修订记「npm scope 不变」的结论作废:`@balsa` 归外部实体、名下 0 包、无公开获得路径,不争取);**域名 = `balsats.com`**(仅下单此一枚);**GitHub 归属 = org `balsats`**——现裁、**迁移后置**(0.5.0 发布后另起 effort 执行;伞形归属,与「balsa 是伞形品牌、framework 是其下第一个子项目」的口径对齐);**X 面 `@balsats` 被个人占用**——接受,不作为条件。首发版本 = **0.5.0**(M1–M5 全部内容、七包;单 tag `v0.5.0`、owner 手工发布,细节归 `docs/ROADMAP.md`「发布节奏」);**数字口径结案**:不对外写数字(沿 [ADR-0001](./0001-lightweight-definition.md);机制可讲)。
  - **事实底座(2026-10-02 本机实测)**:npm `@balsats` 三端点全 404、bare `balsats` 404、`@balsats/core` 404;GitHub org / user `balsats` 均 404;`balsats.com` / `balsats.dev` RDAP 404(仅下单 `.com`);X `@balsats` = 200(个人账号),对照 `@balsajs` = 404。
  - **Considered Options 补记**:`@balsa` 被否——外部实体持有、0 包、无公开获得路径(三端点签名标定,见 balsats-website#9 报告 §3.3);`balsajs` 被否——域名 / npm / GitHub / X 四面全绿,落选于 owner 选择 `balsats`;`getbalsa` / `balsa-run` 被否——报告推荐序 ②③,同落选。
  - 依据 [裁决记录:ADR-0013 追加修订——根 balsats / scope @balsats / GitHub org 迁移后置 / 数字口径结案](https://github.com/0xnicholas/balsa-framework/issues/95) 决议评论(wayfinder 地图 [可发布化](https://github.com/0xnicholas/balsa-framework/issues/94))。

- **修订(品牌名与仓库名 balsats,2026-10-02)**:**品牌名 `balsa` → `balsats`**、**仓库/项目名 `balsa-framework` → `balsats-framework`**——本 ADR 同日的「标识根 balsats」修订记中「**品牌名 balsa 不变**」「**仓库名 `balsa-framework` 不变**」两条作废,标识根与品牌名自此同一(`balsats`);定位句(README 首句兼 repo description)只换名,句法与差异化轴不变。**活面**:根 `package.json` name、七包 description 与 `repository.url`、`README` / `CONTEXT.md` / `AGENTS.md`、`docs/architecture/**`、十 example(脚本 / README / env / 临时目录)与包 README prose、脚本与测试夹具;**文字面之外的 wire 面一并换名**——OTel 属性族 `balsa.*` → `balsats.*`(`span.type` / `run_id` / `thread_id` / `resource_id` / `request.*` / `input` / `output` / `metadata` / `error.details`,见 ADR-0009 同日修订)、resource 默认 `service.name` → `balsats`、mcp-client 桥接 `~standard.vendor` → `balsats`、console exporter 前缀 `[balsats]`、示例 env `BALSA_*` → `BALSATS_*`;细则与核验数字归 `docs/ROADMAP.md` 同名修订行。**代价(实测记账)**:(1) **0.5.0 已于 2026-10-02 上线**(`@balsats/*` 七包)——线上 tarball 内 README 与 `repository.url` **不可回改**,其中旧仓库链接经 GitHub 301 有效,但网页 `/issues/NN` 深链沿本 ADR 2026-09-30 修订记的实测口径仍不可假定(ADR 正文与既有修订记按惯例保留当时的旧名);(2) **wire 面换名是对 0.5.0 消费者的破型**,pre-1.0 窗口内落、随下一版记账;(3) **GitHub 归属(org `balsats`)与侧翼仓名均不在本次改动面内**——org 迁移沿本 ADR 同日修订记「迁移后置」口径不变,`balsa-docs` / `balsa-website` 的改名归各自仓库动线;(4) GitHub 仓库改名与本地目录改名由 owner 在侧翼动线收口后执行(本次只落文档与代码面)。依据:本次 session 裁决(**未立票**,ADR 惯例的决议评论链接暂缺,后续立票可回填)。
- **修订(更名 oribos,2026-10-03)**:**品牌名 `Balsats` → `Oribos`**、**仓库/项目名 `balsats-framework` → `oribos-framework`**、**npm scope `@balsats/*` → `@oribos/*`**——本 ADR 上层两条修订记(「标识根 balsats」与「品牌名与仓库名 balsats」)的品牌 / 仓库 / scope 结论由本行作废,标识根与品牌名自此同一(`oribos`);定位句(README 首句兼 repo description)只换名,句法与差异化轴不变。**落地标识(2026-10-03 本机实测)**:npm `@oribos` scope **FREE**(`@oribos/core` 404、`@oribos` 名下 0 包)、bare `oribos` **FREE**(非 scoped 不争取的理由未变),org 创建依赖 owner 的 npm 账号;**GitHub org `oribos` 已被占**(Organization、created 2020-08-03、7 public repos)⇒ 沿本 ADR「衍生 org 让品牌与仓库地址不同名」的否决策(派生名 `oribosjs` / `getoribos` / `oribos-ai` / `oribosfw` 实测均空但**不采用**),**个人账号同名仓库 `0xnicholas/oribos-framework` 保留完整品牌面**——本 ADR 2026-10-02 修订记「GitHub 归属 = org `balsats`、迁移后置」的口径对 `oribos` **不成立**;**域名 `oribos.com` 已注册**(2016-01-13 注册、2027-01-13 到期、NameBright DNS、clientTransferProhibited)⇒ 不可得,**域名根待 owner 另裁**(`.dev` / `.io` / 派生 `.com` 未标定);X `@oribos` 本机不可达、未标定。**代价(实测记账)**:(1) **0.5.0 已上线,线上 tarball 内 README / `repository.url` / wire 面不可回改**——实测线上 `@balsats/*@0.5.0` 仍是 `balsa.*` 属性族 / `service.name: balsa` / `[balsa]` / `vendor: 'balsa'` 与 "Balsa …" 元数据,即 **`balsats` 一次换名只落在仓库、未随发布上线** ⇒ 下一次发布承载 `balsa.*` → `oribos.*` 的**合并后一次 wire 面破型**(pre-1.0 窗口内落);(2) `@balsats/*` 的 deprecate 指向新名归发布票;(3) **侧翼仓名(`balsats-docs` / `balsats-website`)不在本次改动面**——归各自仓库动线。依据 [改名:balsats → oribos(品牌 / npm scope / wire 面 / 仓库全换)](https://github.com/0xnicholas/oribos-framework/issues/129) 决议。
