# 「轻量」的定义:按需组合 + 无运行时负担

本项目的差异化轴是"轻量",定义为:**按需组合**(用户只为用到的能力付出,核心极小、能力可选挂载)与**无运行时负担**(不强制 DB/队列/长驻进程,随处可跑、嵌入宿主应用而不接管它)。我们刻意不把轻量定义为公开承诺的依赖数/字节数硬指标——那是把代理指标当成价值本身;但数字也不被丢弃:依赖数、构建字节数、安装体积、startup 时间作为内部 CI 回归参考保留(超预算在 PR 上亮黄灯,不卡死、不对外承诺),因为毫无代理指标的克制会在 roadmap 压力下逐 PR 流失(hono 的 CI 字节预算是守住轻量的正例)。

## Considered Options

- **硬性公开预算**(零依赖硬线 + gzip ≤100KB 等,README 承诺 + CI 卡死):被否。公开数字承诺会锁死未来合理的权衡,且字节数不等于用户价值。
- **纯原则自律、不留任何数字**:被否。无代理指标的纪律不可持续。
